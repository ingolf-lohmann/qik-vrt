## 1. Intelligence grows through verifiable sharing

In this work model, intelligence is not a possession that becomes smaller when it is shared. It becomes productive when another observer can receive, distinguish, inspect, criticize, reproduce, and develop it.

Sharing does not automatically establish truth, acceptance, or effect. It first creates a new opportunity for observation. Subsequent inspection may create new evidence. A bound decision may then create development.

```text
INTELLIGENCE
→ SHARE
→ EXTERNAL OBSERVATION
→ NEW EVIDENCE
→ NEW INTELLIGENCE
```

Therefore:

```text
SHARING != ACCEPTANCE
DRAFT != SUBMITTED
SUBMITTED != PEER_REVIEWED
TRANSPORT_ACK != EFFECT_ACK
```

## 2. IED: Intelligence, Evidence, Development

### Intelligence

Intelligence is the ability to decompose an apparently single state into decision-relevant distinctions. In QIK-VRT this especially concerns meaning, evidence, and authority.

```text
MEANING
EVIDENCE
AUTHORITY
```

### Evidence

Evidence binds a statement to verifiable artifacts and observations. Depending on the subject, these may include a repository, commit, tree, predecessor, file, digest, workflow run, kernel check, runtime observation, or external receipt.

Evidence is not mere activity. A workflow start is not successful execution. A transport acknowledgement is not an effect acknowledgement. An implementation is not a canonical effect.

### Development

Development materializes exactly one permissible next continuation from the separated findings. It is not the largest possible change. It is the smallest causally sufficient, history-preserving, and responsible next difference.

```text
INTELLIGENCE
→ EVIDENCE
→ TRIAGE
→ DEVELOPMENT
```

## 3. Make three from one — and one from three

The IED structure follows the triage formula:

```text
ONE
→ DISTINGUISH
→ THREE
→ INSPECT
→ DECIDE
→ ONE
```

One problem is decomposed into independent questions. Their answers are reduced to one next decision without erasing the distinctions.

At the QIK-VRT machine boundary, the next decision can be represented by the four-state D0 ABI:

```text
D0=0  NOOP
D0=1  HOLD
D0=2  REOBSERVE
D0=3  REQUEST_AUTHORITY
```

The selection remains dynamic. When the head, tree, evidence, predecessor, or authority changes, triage is repeated. The optimum is therefore not an eternal final state, but the best permissible continuation under the currently bound state.

## 4. The repository as a sharing and proper-time mechanism

A QIK-VRT repository shares more than text. It binds content to history.

```text
TREE   = content state
COMMIT = event identity
PARENT = historical predecessor
BRANCH = local development line
```

Two commits may carry the same tree and still be different events. The same state type can recur at a new local time position without overwriting the earlier event.

```text
1[n] → IED[n] → 1[n+1]
```

This yields a local, causally advancing repository time. A packet may transport the binding of information to that local history. It does not transport physical time itself and does not prove communication into one's own physical past.

## 5. What is to be shared

The dissemination mandate names distinct venues. They must not be collapsed into one publication status.

### GitHub

GitHub is the primary versioned source and development space. It binds wording, claim boundaries, artifacts, tests, reviews, and integration history.

### Zenodo

Zenodo is an archival and identifier route. A prepared package is not a publication. A DOI may be reported only after public publication has been observed and the public bytes have been reverified.

### IETF

The IETF route concerns protocol and interoperability, especially Effect Acknowledgement. A repository document or Internet-Draft candidate is not Working Group consensus, IETF approval, or an RFC.

### arXiv

The arXiv route is a preprint route. A frozen source package is not a submission; a submission is not an announced record and is not peer review.

### Wikipedia

Wikipedia is not a substitute for primary publication or independent reception. A neutral encyclopedic treatment requires suitable independent secondary sources. Repository artifacts can provide source material, but do not by themselves establish independent notability.

### IEEE

The IEEE route requires a concrete journal or conference, a venue-specific manuscript, reproducible evidence, a clear contribution statement, and compliance with the applicable submission rules. A cover letter is not a submission; a submission is not acceptance.

### E-mail correspondence

Correspondence must be recipient-specific. A draft without a resolved real recipient remains a draft. Sending, receipt, and response are separate events.
