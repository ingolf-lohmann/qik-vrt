# Das virtuelle Gestern antwortet dem Heute

Status: **`REPOSITORY_NOTE_NOT_ZENODO_CANDIDATE`**\
Autor: **Ingolf Lohmann**\
Datum: **2026-08-03**

Diese additive Forschungsnotiz bewahrt den Aphorismus zur Retrokausalität und
trennt seine poetische, semantische, kausale und protokolltechnische Lesart.
Sie verändert weder das veröffentlichte Bündel unter DOI
`10.5281/zenodo.21711193` noch die laufende, exakt gebundene
VRTCore-H3-Publikationsrecovery.

## Tragfähige wissenschaftliche Fassung

Ein heute vorhandenes Artefakt kann ein früheres Ereignis repräsentieren oder
etwas darüber behaupten. Seine heutige Rezeption kann heutige Wahrnehmungen,
Modelle oder Entscheidungen beeinflussen. Eine solche Wirkung verläuft
vorwärts in der Zeit und verändert das referenzierte frühere Ereignis nicht.

`antwortet` ist dabei eine Metapher. Die Repräsentationsrelation ist semantisch.
Ein behaupteter Einfluss auf eine heutige Entscheidung benötigt eine eigene
Evidenzbrücke; bloße zeitliche Folge, Zugriff oder Korrelation genügt nicht.

- `VPR-001` — interpretative Lesart des „virtuellen Gestern“;
- `VPR-002` — quellengebundene Abbildung auf verkettete, unveränderte

- `VPR-003` — physikalische oder ontische Retrokausalität bleibt offen.

Die drei Claims sind in [CLAIM_MATRIX.json](CLAIM_MATRIX.json) maschinenlesbar
klassifiziert. [EVIDENCE_BOUNDARY.md](EVIDENCE_BOUNDARY.md) benennt die
Geltungsgrenzen. [CORRECTION_NOTICE.md](CORRECTION_NOTICE.md) korrigiert die
zuvor nur im Chat behauptete, tatsächlich nicht belegte Commit-/Hash-/CI-Kette.

## Publikations- und Protokolldisposition

- **GitHub:** additive, reviewbare Repository-Notiz;
- **Zenodo:** kein neuer Record und keine neue Version für diesen Aphorismus;
- **EFFECT_ACK:** keine Änderung der fünf Zustände, des Wire-Formats oder des
  DONE-Prädikats;
- **IETF:** keine neue Revision allein für diese Klarstellung; Revision `-03`
  enthält die benötigten normativen Regeln bereits.

Eine epistemische Klassifikation wählt keinen EFFECT_ACK-Zustand. Ohne einen
vorgeschlagenen nachgelagerten Effekt ist EFFECT_ACK nicht anwendbar. Für einen
Commit, eine Publikation oder eine Submission wird der Zustand aus dem jeweils
vollständigen, gebundenen Entscheidungsrecord abgeleitet.
